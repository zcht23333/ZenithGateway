# 限流在途命令计数：生命周期与并发退役

2026-10-07。本轮修复 `RedisRateLimiter.Command` 的计数竞态，范围限于诊断正确性、确定性复现及相关回归。运行配置、Redis 额度算法、故障策略、资源配额和交接默认值均不变。原一小时样本仍只对应旧包；RSS 归因留待本轮验收之后。

## 缺陷与修复

原实现先用 `waiting.compareAndSet(true, false)` 认领终态，再执行诊断时间记录，最后递减 `inFlight`。如果胜出的回调暂停在认领与递减之间，工作线程的第二次 `observed()` 会看到 false 并直接返回；它可以开始下一条命令，而上一条计数仍未扣除。因此一个工作线程、实际只有一个 waiting 标志时，当前值与累计峰值可能都变成 2。

修复将 `waiting` 判断、`inFlight` 递减和退役标志发布放入同一命令对象的 `retire()` 临界区，正常结果、异常结果与物理关闭共用这个入口。只有胜出者返回 true，才更新对应终结遥测。重复观察者必须等这次扣减完成后才能返回，工作线程不能带着未扣除的旧计数派发下一条命令。

锁只覆盖常数步状态操作，不执行 I/O、诊断回调、耗时记录或下游代码；不同命令不共享此锁。诊断中的 `saturation.enabled()` 即使被夹具暂停，也不会阻塞重复观察者或造成额外计数。没有采用截断计数、限制峰值为 workers、取消时提前清零等掩盖异常的做法。

这是一个短临界区方案，仍受线程调度暂停影响，不是无锁算法。当前值与峰值分别通过原子计数器更新，整个诊断 JSON 及遥测直方图依然不是原子快照；精确结算对账在静止后进行。峰值记录真实客户端计数增加时的最大值，实例启动后不会重置。

## 计数生命周期

| 事件 | 当前值变化 | 含义 |
| --- | --- | --- |
| 创建额度 EVAL / 恢复探测的 Command，进入客户端派发尝试 | +1，并更新累计峰值 | 尚无可观察结果或已确认物理关闭；包含同步派发异常的待清理尝试，不等于已写入 Redis |
| Future 完成回调，或工作线程 `get()` 返回后观察同一结果 | 第一个退役者 -1 | 包括正常值和异常终态；`commandResultsObserved` 只增加一次 |
| 请求超时、取消或中断 `get()` | 本身不减 | HTTP/额度决定终止不代表底层命令消失。已有结果可正常退役；否则继续保留到物理关闭确认 |
| 没有已观察终态，但连接关闭得到确认 | 第一个退役者 -1 | `commandsAbandonedAfterClose` 增加一次；不推断 Redis 未执行、不退还令牌 |
| 迟到结果、重复回调或后续重复关闭 | 0 | 不二次结算、不产生负数、不抹去累计峰值 |
| 排队取消、本地拒绝、显式关闭限流 | 不创建 Command，不增加 | 决策计数与命令计数保持不同口径 |

`commandsInFlight` 是客户端尚未完成上述退役的派发尝试数，包含恢复探测，排除结果解析、同步下游处理、结果交接和审计。它不是 Redis 服务端正在执行的命令数，观察到异常 Future 终态也不代表扣费已确认。连接不能确认关闭时继续沿用隔离槽与故障策略；本轮不修改这些边界。
