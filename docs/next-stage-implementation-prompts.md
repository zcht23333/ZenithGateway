# 下一阶段实施交接指令
日期：2026-09-25

配套资料：[设计准备稿](next-stage-design-preparation.md)。先使用指令 A；运行概览完成并通过验收后，再使用指令 B。两段指令独立成任务，不要求一次完成两个页面。

## 指令 A：公共基础与运行概览

请直接实施 ZenithGateway「公共基础 + 运行概览」改造。项目位于 D:/Java/ZenithGateway。

开始前阅读 docs/next-stage-design-preparation.md、docs/route-polish.md 和相关源码，并查看当前运行页面。已验收的路由页是视觉基准；本次主要交付是 / 的运行概览。系统配置的主体改造留到下一阶段。

目标：让三页属于同一产品，同时让运行概览拥有清楚的主角。方向继续使用「交通调度的清晰 + 轨道控制室的张力」。

已认可的视觉基准：
- 深石墨背景、黄绿色选中与主要动作、浅色工作表面，沿用 route-dispatch.css 的颜色与字体。
- 主要正文 15–16px，明暗和画面比例建立主次。
- 亮度集中于当前焦点，普通状态克制，选中与展开有明确反馈。
- 已验收的路由路径、目录选择、节点展开和长字段行为保持。

请完成：
1. 最小化提取公共品牌、导航和必要样式，不重建组件库。三页导航名称统一为「运行概览 / 路由调度 / 系统配置」；窄屏三个入口都可到达。认证、断开管理连接和明确标注的演示模式保持有效。
2. 把 QPS、P95 和真实时间趋势放进概览的首屏主体。窗口请求数和统计窗口辅助解释；平均延迟、取消与未知状态不抢主视觉。
3. 优先尝试共用时间轴、上下对齐的流量与延迟趋势，可根据实际浏览器效果调整构图。时间间隔、单位和数据缺口准确；继续使用现有 ECharts。
4. 审计先显示待写入、最长等待及简短状态，再展开详细计数。最近审计记录采用可读的浅色工作区；方法、结果、耗时、事件时间清楚，长路径能完整查看或复制。
5. 分别处理各数据源的加载、失败、旧数据和恢复；保留真实的订阅与轮询生命周期。

必须遵守的数据规则：
- 「实时请求流」改成「最近审计记录」。现有接口约每 5 秒读取最近至多 40 条，并非逐条实时推送。
- 无数据不能默认为零；真实零、等待、失败、旧数据与监控关闭分别表达。
- 流量使用 windowSeconds 所示窗口；趋势至多保留 120 个采样点，采样间隔可能变化。不要增加无后端支持的 1h / 24h 选择。
- P95 = -1 按超过 60,000ms 表达；图表注明超范围。
- cancelled、errors、unknownStatus 不能与状态码桶相加充当总请求数。
- 审计累计丢弃不等于当前故障；结果未知可能已经写入；当前窗口为零仍可能存在较早的审计记录。
- SSE 连接状态不代表上游健康。现有数据没有 routeId，不新增假链路、逐路由指标或健康评分。
- 流量、审计状态、最近记录独立失败和恢复，不能用一处失败覆盖整页。

布局比例与细节可以发挥，但真实数据语义、已验收功能和可读性必须满足。实现过程中通过实际截图检查主次，必要时自行迭代，不停留在文字方案。

验收与交付：
- 提供 1440×900 正常首屏、390px 页面，以及空数据、局部失败/旧数据、审计异常的代表截图；异常场景通过明确标注的演示或隔离测试注入。
- 提供 10–20 秒实际交互录屏，覆盖趋势查看、审计展开和完整记录查看。演示记录与真实后端检查分别说明。
- 公共代码调整后检查路由长名称、全部目录搜索选择、节点展开、认证与异常恢复。
- 运行现有前端测试、生产构建，为新增状态逻辑补充必要测试；如使用预览，不得请求真实后端。
- 交付可运行页面、实际验证结果、设计说明和剩余取舍。不以截图中的假数据代替真实接口能力。
- 本阶段完成后交付验收，不继续改造系统配置主体。

## 指令 B：系统配置

请在已经验收的公共基础与运行概览之上，实施 ZenithGateway /settings 系统配置改造。

开始前阅读 docs/next-stage-design-preparation.md，以及上一阶段实际设计与验证记录；查看当前配置页、Settings.vue、traffic.ts 和 RuntimeConfigController.java。沿用已建立的公共导航、字级、配色和控件。

页面任务：清楚说明「现在用什么值、我改了什么、服务端确认了什么」。以浅色参数区为主要工作空间，旁边呈现「当前 → 待保存」变化摘要；移动端按自然阅读顺序纵向排列。画面需要延续产品性格，布局可依据真实内容调整。

只改造现有六个字段：
- 全局限流：rateLimitEnabled，boolean；统一开关，按 IP 的令牌桶。
- 令牌补充速率：replenishRate，整数 1–10,000，单位「令牌/秒」。
- 令牌桶容量：burstCapacity，整数 1–10,000，单位「令牌」。
- 单次请求消耗：requestedTokens，整数 1–100，单位「令牌/请求」。
- 指标统计窗口：monitorWindowSeconds，整数 1–120，单位「秒」。
- 快照推送间隔：emitIntervalSeconds，整数 1–5，单位「秒」。

使用两个分组「流量控制 / 监控采样」。每项用普通中文简要说明影响。令牌补充速率不能继续写成 req/s；关闭限流保留参数并说明重新启用后使用。不要增加接口没有的监控开关、审计开关、配置历史或回滚版本。

必须完成的交互：
1. 初次读取成功后才建立当前配置和表单基准；读取中、失败与重试清楚。不能把本地默认值作为已生效配置提交。
2. 变化摘要只显示变更字段；未修改或输入无效时不能保存；可以恢复当前已读取值。
3. 字段标签正确关联输入；空值、小数、非数字和越界有就地提示。不要静默改值或自行发明后端约束。
4. 保存中防止重复提交和结果覆盖新草稿；失败保留草稿。有未保存修改时离开不能静默丢失。
5. 使用 GET /settings/runtime 和 PUT /settings/runtime。以 PUT 返回的服务端有效配置更新基准。
6. 明确区分：确定写入失败、网络中断导致结果不确定、写入已成功但后续读取失败。结果不确定先提供读取确认；PUT 成功后 GET 失败不得显示成保存失败。
7. 401 走现有管理认证流程，不把草稿当作已保存；必要的反馈包含可操作的恢复入口。

不新增后端接口和依赖。不要在当前运行网关上为了录屏随意改参数；演示使用明确标注的隔离数据，真实保存检查使用独立测试后端并恢复测试配置。

交付：
- 1440×900、390px 实际截图；读取失败、未保存差异、无效输入、保存失败与成功的代表状态；320px 检查溢出。
- 10–20 秒实际录屏：修改参数 → 查看差异 → 保存反馈，注明演示或独立真实后端。
- 校验字段边界、写入结果不确定、写成功后读取失败、认证失效和离开时的草稿保护。
- 运行现有测试、生产构建和必要的浏览器检查；记录实际结果与未覆盖部分。
- 检查公共导航和已验收两页没有退化，交付设计与验证说明。
