## 1. 本轮结论与边界

下一轮先做「公共基础 + 运行概览」，验收后再做「系统配置」。已验收的路由页是共同的视觉基准，保留其路径画布、浅色目录、选择与展开逻辑。

共同方向是「交通调度的清晰 + 轨道控制室的张力」：清晰来自真实的信息顺序、单位、状态和操作反馈；张力来自画面比例、明暗和焦点。两页各有主角：概览突出趋势，配置突出可控的变更。不要把路由路径图原样搬进每个页面。

本稿中的数据含义、已有功能和异常恢复是硬约束；布局比例、留白、图表编排、动效细节是建议，可在真实浏览器中比较后调整。没有要求再扩展视觉风格清单，也没有新增后端接口、配置历史或监控部署任务。

## 3. 公共视觉与交互基准

沿用现有路由页的颜色，先提取必要的公共变量，避免重建组件库或一次性重写状态管理。

| 用途 | 基准 |
| --- | --- |
| 深色工作背景 | #0b1317 |
| 浅色工作表面 / 深色文字 | #f3f1e7 / #19242c |
| 深色区主要 / 次要文字 | #f0f1e9 / #a8b7bb |
| 深色区分隔线 | #2b3c43 |
| 选中与主要动作 | #c4f374 |
| 需要注意 / 失败 | #edbe71 / #ffb0a7 |
| 中文字体 | 沿用 Segoe UI、Microsoft YaHei、PingFang SC 系统字体栈 |
| 字级 | 页面标题约 28–34px；主要正文 15–16px；字段与操作 14–16px；辅助标注 12–13px |
| 控件 | 明确焦点、悬停和禁用状态；延续约 4–6px 的小圆角；移动端操作保留足够点击范围 |

规则：

1. 共用品牌、导航名称「运行概览 / 路由调度 / 系统配置」、当前页指示、认证入口及基础按钮。页面内容区按任务组织，不复制统一卡片矩阵。
2. 黄绿色聚焦当前操作和主数据；警告、错误同时提供文字或图标。浅色表面不能直接照搬深色区的浅黄、浅绿文字，应使用可读的深色版本。
3. 概览的识别特征是贯穿主区的时间坐标；配置的识别特征是浅色参数区与「当前 → 待保存」变化摘要。减少无意义的编号、英文小字和发光描边。
4. 平时保持安静，悬停、选中、展开时再增强反馈；尊重减少动效设置，不用持续流光假装真实流量。
5. 1440×900 保证核心任务优先可见；390px 改为自然纵向阅读。窄屏不能把非当前页面入口全部藏掉且没有替代入口。
6. 公共导航若保留全局指标，用可选区域承载；概览避免把同一组指标重复放在页头和主体两处。
7. 认证与演示模式继续明确区分。现有 /routes/preview 的无后端演示行为保持；如增加新预览，应显式配置入口及数据来源，不能按宽泛路径绕过认证。

## 4. 运行概览：建议的页面结构

页面优先回答三个问题：**数据是否新鲜？流量与延迟怎样变化？审计写入是否需要处理？**

### 桌面布局方向

| 区域 | 内容与优先级 |
| --- | --- |
| 公共页头 | 品牌、三个导航入口、管理连接 |
| 页面开头 | 「运行概览」、流量更新状态、最后更新时间；必要的重试入口 |
| 深色主区 | QPS 与 P95 为主要数字；窗口请求数及统计窗口辅助说明；下接占据主要宽度的真实时间趋势 |
| 审计摘要 | 待写入数量、最长等待、状态说明；展开后查看详细计数、容量和内存 |
| 浅色记录区 | 最近审计记录；方法、完整路径访问入口、结果、耗时、事件时间；独立显示读取状态 |

建议先尝试共用时间轴、上下对齐的 QPS 与 P95 两条图，分别标明 req/s 与 ms。也可提出清晰的替代构图，但不要让双轴重叠误导比较。用实际 timestamp 定位时间和间隔；缺失段、P95 超范围或统计关闭不能连成虚假的连续趋势。

首屏验收以实际浏览器为准：在 1440×900 的正常状态下，应能读到主要指标、趋势主体和审计摘要；最近记录允许向下延伸。不要为了塞进首屏把文字缩回 11px。

### 数据和时间范围

| 数据 | 现有来源 | 必须保留的含义 |
| --- | --- | --- |
| 当前窗口指标 | GET /dashboard/snapshot，后续 SSE traffic 事件 | requestCount 为窗口内已结束的代理请求数；qps 为窗口平均值，窗口以 windowSeconds 为准 |
| 趋势 | GET /dashboard/series?size=120，后续追加 SSE 快照 | 前端保留至多 120 个采样点；采样间隔可变，不等于固定两分钟或任意历史区间 |
| 流量更新 | GET /settings/sse-token 后建立 /monitor/stream | SSE 连接仅说明指标更新通道状态，不代表所有上游健康 |
| 审计状态 | GET /monitor/audit/status；现有约每 5 秒轮询 | pending = queueDepth + inFlight；展示审计自身状态及数据新鲜度 |
| 最近审计 | GET /monitor/audit/recent?size=40；约每 5 秒轮询 | 从 Redis 读取最近至多 40 条审计记录；与当前窗口范围不同，可包含当前进程启动前的记录 |

补充规则：

- 尚未读到数据显示「— / 读取中」；真实 0 可以显示为 0；读取失败保留已有值时，明确标注旧数据与时间。
- 流量监控关闭与流量为零分别表达；SSE 中断不抹掉仍能更新的审计数据；审计读取失败也不让整页流量报错。
- p95LatencyMs = -1 表示超过 60,000ms；数字区可显示「> 60,000ms」，图表应标注超范围，不能画成 -1、0 或无说明地消失。
- cancelled、errors、unknownStatus 与 HTTP 状态分组可能重叠，不能相加当作请求总量。
- 审计累计丢弃、结果未知、重试数属于本次进程运行；历史累计非零不能直接表示此刻仍故障。pending 非零本身也不等于故障。
- persisted 表示收到 Redis 写入确认；uncertain 表示没有得到确认，可能已经写入。文案避免把它解释成确定丢失。
- statusCode = 0 显示「未形成 HTTP 状态」等准确文案；outcome = cancelled 明确取消，不伪造 HTTP 状态。
- 最近记录展示事件时间，另显示最近读取时间；跨日时提供日期。长路径可展开或复制完整值。
- 现有记录没有 routeId，不承诺准确的逐路由链路分析、单路由 QPS 或追踪跳转。
- 不添加没有真实来源的健康总分、在线服务数、SLA、24 小时趋势和成功率口径。

## 5. 系统配置：建议的页面结构

页面优先回答三个问题：**现在使用什么值？我改了什么？服务端最后确认了什么？**

桌面以浅色参数工作区为主，旁边保留较窄的变化摘要和动作区；窄屏将摘要放到表单下方。组织为两个明确分组，继续使用现有六个参数。

| 分组 | 字段 | 推荐标签 / 单位 | 后端有效范围 |
| --- | --- | --- | --- |
| 流量控制 | rateLimitEnabled | 全局限流 / 开关 | boolean |
| 流量控制 | replenishRate | 令牌补充速率 / 令牌·秒⁻¹ | 整数 1–10,000 |
| 流量控制 | burstCapacity | 令牌桶容量 / 令牌 | 整数 1–10,000 |
| 流量控制 | requestedTokens | 单次请求消耗 / 令牌·请求⁻¹ | 整数 1–100 |
| 监控采样 | monitorWindowSeconds | 指标统计窗口 / 秒 | 整数 1–120 |
| 监控采样 | emitIntervalSeconds | 快照推送间隔 / 秒 | 整数 1–5 |

标签下用一句普通中文解释影响。全局限流是统一开关，现有桶按 IP 生效，不是所有请求共用一个总额度。令牌速率不直接叫 QPS；单次消耗大于 1 时二者不同。可用静态关系说明辅助理解，但不能把说明图做成实时桶余量。关闭限流后参数值仍有含义，应保留；明确其会在重新启用后使用。

只支持 GET /settings/runtime 与 PUT /settings/runtime 现有接口。monitorEnabled、auditEnabled、审计容量等不在六个可写字段内，本轮不新增相应开关。

### 保存与恢复状态

| 状态 | 用户应看到什么 / 可以做什么 |
| --- | --- |
| 初次读取 | 明确读取中；不以本地默认值冒充已生效配置，不允许提交未知基准 |
| 初次读取失败 | 就地说明、重试；可保留结构，不能静默进入可保存状态 |
| 已读取、无变更 | 展示当前值和已读取状态；保存按钮不可重复提交 |
| 有未保存变更 | 摘要只显示发生变化的字段及「当前 → 待保存」；提供恢复当前已读取值的动作 |
| 输入无效 | 字段旁说明范围；空值、小数、非数字和越界均明确处理，不自动吞掉输入 |
| 保存中 | 显示提交状态并防止重复提交；避免用户在提交时改值导致结果覆盖新草稿 |
| 写入成功 | 以 PUT 返回的服务端有效值更新当前基准；正常情况无需为了展示成功重复写入 |
| 写入失败 | 保留草稿和差异；明确失败原因及再次操作入口 |
| 写入结果不确定 | 网络超时等不能断言服务端未写入；保留草稿，先读取确认再决定重试 |
| PUT 成功、后续 GET 失败 | 如果保留保存后读取，提示「保存已确认，重新读取失败」，保留 PUT 的有效返回值 |
| 认证失效 | 走现有认证流程，说明尚未保存；不把草稿当作已生效配置 |

未保存状态下切换页面应防止无提示丢失修改，确认只针对确有未保存变更。以本次读取作为比较基准，不新增版本号或多人编辑冲突协议。若发现字段组合可能使请求无法通过，应给准确解释，不自行改变后端语义或添加臆造的范围规则。

## 7. 验收清单

### 共同基准

- [ ] 1440×900 主要内容清楚，390px 能正常阅读与操作；320px 核查表单、导航与长内容溢出。
- [ ] 三页导航、字号、按钮、焦点一致；浅色与深色区文字均清楚；键盘能完成主要任务。
- [ ] 未伪造数据、时间区间、健康判断或当前请求流动。
- [ ] 演示场景明确标注；演示不请求真实后端；正式页保留认证。
- [ ] 提取公共代码后复查路由正常、长名称、目录搜索与选择、节点展开、异常恢复和认证，避免已验收能力退化。

### 运行概览

- [ ] 真正零流量、初次等待、无历史、监控关闭、旧数据各自可辨。
- [ ] snapshot / series / SSE / 审计状态 / 审计记录任一失败时，其他可用部分继续工作，并能恢复。
- [ ] 非等间隔样本、断流和 P95 超范围表达正确；窗口单位、采样范围与轴标签一致。
- [ ] 当前窗口为零而仍有历史审计记录时不会自相矛盾。
- [ ] 审计累计异常与当前状态分开；结果未知不被当作确定丢失。
- [ ] 长路径可完整查看；跨日记录时间清楚；取消与未知 HTTP 状态正确。
- [ ] 离开页面后释放订阅、轮询和图表，返回时不会叠加更新。

### 系统配置

- [ ] 读取失败不会提交本地默认值；重试成功后才能建立当前配置。
- [ ] 六个字段标签、单位、上下限与后端一致；空值、小数和边界值经过验证。
- [ ] 仅有有效变更时允许保存；恢复已读取值准确；有草稿离开不会静默丢失。
- [ ] 保存失败保留草稿；重复点击不会重复写；服务端有效返回值成为新基准。
- [ ] 明确区分确定失败、结果不确定、PUT 成功后读取失败和认证失效。
- [ ] 使用独立环境完成一次真实读取、修改、确认及恢复，不以演示交互冒充后端验证。

完成对应阶段后运行现有前端测试与生产构建，并补充与新增状态逻辑有关的有意义测试。记录实际通过项和未覆盖项，不沿用上一轮测试数量。
