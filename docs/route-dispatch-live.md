## 本轮接入内容

保留已确认的主路径、底部目录、就地展开、完整字段复制及移动端交互。正式页面移除概念标记和演示场景按钮，导航指向正式入口，并提供断开管理连接操作。

| 情况 | 正式页面行为 |
| --- | --- |
| 首次请求尚未完成 | 显示正在读取，不提前显示“配置已读取”或创建空目录入口。 |
| 成功读取空列表 | 显示创建第一条路由。 |
| 首次读取失败 | 说明尚未取得配置，提供集中重试入口。 |
| 已有配置后刷新失败 | 保留当前路径与目录，标记使用缓存，暂停编辑、创建和删除。 |
| 保存或删除成功，但随后列表刷新失败 | 分别说明写入结果与刷新失败；警告使用琥珀色，不把成功写入当作失败重试，也不让不存在于缓存中的新 ID 清空当前画布。 |
| 全局限流配置不可用 | 节点标注配置未获取，不推断放行或画出超额分支；路由自身读取正常时仍可编辑路由。 |
| 流量指标或审计状态不可用 | 显示“—”与展开后的错误原因，不以零或旧值表示成功。 |
| 监控统计关闭 / P95 溢出 | 保留已有语义：统计关闭显示“—”；P95=-1 显示“> 60,000 ms”。 |
| 退出或凭据失效 | 使用原有登录流程，并取消已卸载页面的请求和轮询。 |

路由由用户手动刷新；全局配置、统计和审计状态每 5 秒读取。集中刷新会同时重试路由和全局读取，并防止重复的全局读取与定时任务。路径仍是配置视图，节点请求示例仍为明确标注的规则推导。

## 复现联调

要求 Java 21、Docker、已构建的 backend/target/zg-1.0.0.jar、正在运行的前端，以及本地工具目录中的 Playwright。Windows 默认使用本机 Edge，其他环境使用已安装的 Playwright Chromium。

~~~powershell
npm install --prefix .dev/browser --no-save --no-package-lock playwright@1.63.0
docker pull redis:7.4-alpine
node verification/route-dispatch-live.mjs
~~~

脚本优先使用 JAVA_HOME，或已有的本地工具清单；可通过 ROUTE_CONSOLE_URL 更改前端地址，BROWSER_CHANNEL 更改浏览器通道。测试脚本会自行创建并清理独立后端、测试上游和 Redis 容器，不需要切换当前开发服务器的 API 代理。

后续调整可直接以正式页面为基础。概念预览继续用于长名称、异常和密集目录的视觉回归。
