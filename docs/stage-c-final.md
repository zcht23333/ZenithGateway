## 1. P95：数值曲线与超范围标记分开

原先以 60,000 定位三角形并将纵轴扩到 65,000，30–100 ms 的日常变化几乎成为直线。现在数值曲线仅根据真实范围内读数定标；后端 -1 保持为“> 60,000 ms”，在同一时间轴下方的独立事件带标记，不接入数值纵轴。

事件带有独立分隔与文字说明。曲线在超范围采样处留空；孤立的有效采样保留小点，不跨空值连接。悬停、键盘滑块和当前窗口大数字继续显示各自的真实语义。若全部 P95 均超范围，则不显示无来源的数值刻度，并说明“暂无范围内 P95 读数”。

没有把 -1 当成 0、60,000 或任何估算值。后端只提供超限信号，无法得知这些采样的精确延迟。范围内数值仍用线性刻度，极大的真实范围内数值仍会扩展纵轴。

## 2. 加载：先通过认证，再加载页面和图表

router 原先静态引入全部三个页面，概览再静态引入 ECharts。现在路由只引用轻量的 AsyncPage 宿主：App 的认证门通过后才挂载宿主并 import 对应页面。只使用普通的 Vue Router 懒路由仍可能在认证 UI 出现前解析页面，因而这里将加载边界放在认证门内部。

概览先呈现数值、数据状态与审计区域，再独立加载 chart 模块中的 ECharts。图表等待或失败不阻塞其他数据源，离开页面后晚到的模块不会创建孤立画布。页面和图表资源失败提供明确提示及手动“重新载入页面”。浏览器会缓存失败的模块导入，简单重复 import 不能保证恢复，因此不提供无效的局部重试，也不自动刷新。重载仍受现有 beforeunload 草稿提醒约束；正式页重新读取并在需要时认证。

同时消除按页拆包后显露的样式隐性依赖：复制按钮样式归入 DispatchCopy，认证草稿提示归入公共样式。概览无需先访问路由页就能完整显示复制控件。

## 3. 手机：在编辑与核对之间建立短入口

单列布局且草稿有变化时显示“已修改 N 项 · 查看变更”。入口位于参数区的正常文档流中，浏览时吸附在顶部；输入获得焦点时取消吸附，不覆盖正在编辑的字段和紧邻的错误说明。没有底部悬浮按钮。

点击后将焦点交给完整的变更摘要标题，并滚动到核对区；当前值、待保存值、校验与服务端确认继续完整保留。恢复当前值或保存确认后，差异消失，入口随之消失。减少动效设置下直接定位，不平滑滚动。

已检查 390×844 和 390×480 缩小视口。后者是软件键盘占用空间的布局模拟，不代表完成了实体手机 / 原生输入法验证。桌面仍保留原侧边核对区。

## 复现

在根目录导入已有工具链，启动前端生产预览后执行：

~~~powershell
. ./.dev/upgrade-tools/env.ps1
npm --prefix frontend test
npm --prefix frontend run build
npm --prefix frontend run preview -- --host 127.0.0.1 --port 15175
~~~

另一个终端：

~~~powershell
. ./.dev/upgrade-tools/env.ps1
$env:ROUTE_CONSOLE_URL = 'http://127.0.0.1:15175'
node verification/stage-c-browser.mjs
$env:STAGE_C_PHASE = 'after'
node verification/stage-c-network.mjs
# 需 Docker、已有 redis:7.4-alpine 镜像和 backend/target/zg-1.0.0.jar
node verification/stage-c-showcase.mjs
~~~

网络脚本自行启动临时生产静态服务器；before 使用保留的 .dev/stage-c/dist-before，after 使用 frontend/dist。初始源码与已验收素材保存在 .dev/stage-c/before.zip，均不会自动重建为当前源码。所有独立后端测试都会在 finally 中恢复配置并清理自己的资源。
